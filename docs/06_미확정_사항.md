# 개발 중 확인이 필요한 미확정 사항

이 문서는 **사용자가 이미 확정한 규칙을 변경하지 않기 위한 안전장치**입니다. 아래는 자동 구현 시 해석이 갈릴 수 있는 사항입니다. 새 세부 규칙을 연속 질문하지 말고, 실제 구현을 막는 것만 모아 확인하세요.

## 우선순위 높음
1. **카드 조합 제압의 완전한 우선순위:** 틀은 싱글/페어/닐리리를, 마대는 틀/쌍카를 제압한다고 정해졌지만, 예를 들어 마대 vs 닐리리, 불돼지 vs 특정 조합, 사사끼의 정확한 조합 인식 범위 등 전체 매트릭스가 불완전합니다. 기본 조합을 구현하기 전 사용자 확인 필요.
2. **특수 행동 창과 일반 턴 경계:** 찼다/무르기/꽂다를 언제까지 누를 수 있는지, 마지막 카드 완주 잠정 상태가 언제 확정되는지, 5초 꽂다 창과 8초 턴의 정확한 상호작용을 테스트 가능한 이벤트 규칙으로 고정해야 합니다. 기존 '찼다 즉시 확정'과 '무르기 동시 배치 우선'을 유지하세요.
3. **배려판에서 '알 획득'의 의미:** 순수하게 이번 판 정산이 플러스인지, 묻어둔 알 회수까지 포함하는지, 물판은 실패인지 등의 정확한 조건을 확인하세요. 기존 표현은 '알을 획득하면 생존'입니다.
4. **2v2 지급 부족 정산의 일반식:** 확정된 10/2 예시는 있으나, 양쪽 모두 부족하거나 기존 배려판 사용자가 있는 상황을 포함한 완전한 알고리즘이 필요합니다. 예시와 '승자 동일 지급, 초과분 묻기' 원칙을 어기지 마세요.
5. **게임방 생존/복구:** 모두 퇴장한 뒤 1시간 보존은 확정. 서버 재시작 후에도 복구해야 하는지와 보존된 정산 기록의 보존 기간은 운영 선택 사항입니다.

## 구현 가정으로 처리해도 되는 항목(규칙 변경 금지)
- 방 ID, 임시 복귀 토큰 형식, UI 레이아웃, 색상, 애니메이션 프레임은 기술적 선택.
- '서버 동일 처리 단위'는 하나의 이벤트 루프 배치/직렬화 규칙으로 명문화하고 테스트할 것.
- 개인정보/보안: 다른 플레이어 손패가 유출되지 않도록 권한 검증.

## 개발 원칙
- 규칙을 임의 확정하지 말 것.
- 명세와 구현이 어긋나면 우선 테스트를 만들고 사용자에게 **필수 쟁점만** 질문할 것.
- UX 사소한 선택은 합리적인 기본값으로 구현하되 기존 확정 사항은 변경하지 말 것.
